# Actual client-entry key qualification

The three adoption chords passed through the actual compiled client entry and
installed fleet helpers in a private full Imagine fixture. The
[receipt](evidence/native-imagine-keys/receipt.json),
[invocation](evidence/native-imagine-keys/invocation.json) and
[source index](evidence/native-imagine-keys/proof-index.json) identify the
exact input, compiled module and runtime binaries.

- Mod+Enter opened native Kitty, ordinary OpenSSH `-tt`, and a canonical managed
  direct UUID. NAS registration reported direct/nonresumable, no holder socket
  or holder version, and no new persistent session. Native OSC133 prompt state,
  OSC7 `kitty-shell-cwd://nas/home/tom`, `TERM=xterm-kitty` and pinned NAS
  terminfo were observed.
- Mod+Ctrl+Shift+Enter opened the actual native fzf session menu. Text/key input
  into that private menu selected an existing saved session; the real chooser
  resumed its exact UUID and preserved the original NAS fish PID/start.
- Mod+Shift+Enter opened a local rescue fish with no managed NAS identity and
  zero additional SSH invocations.

The exact dirty owner entry was preserved as the source boundary. Its original
SHA256 is `b6cf824a58a96efe6ec8f7d4d674e9a2cf9dff771524a81e4ef96033c0ad4fb9`;
the three-chord patch produces
`61d031227c1e7f731f72046a148f224a20be2ed4b57a01b6c8a3426a5bd9d72d`.
The fixture copies those patched bytes unchanged and supplies only a private
relative-import bridge to the already qualified full Imagine bundle. The
installed builder's `bundle()` resolves the real SDK/default command modules;
the entry's original `ownedChords()` runs when the shell imports. Compilation
uses the existing store dependencies inside a private network namespace and
performs no dependency installation. The compiled module SHA256 is
`aeaf8c394a52e3240353a5a671c70dcc78de3fb024a870c33b7387c56131ca0a`.

The test dispatches actual engine key events through CDP to the registered
shortcut route. It never substitutes a direct test invocation of desktop,
menu or rescue for a shortcut. Menu selection uses Kitty's native remote
control to deliver text/Enter to its real fzf TTY; the initial menu chord uses
the actual engine route. A read-only no-UI kitten observes Kitty's native OSC7
screen field because Kitty 0.50's ordinary `ls` output omits that field.

The original startup exports remain in the copied entry but are intentionally
unactivated in this shell-only private configuration. The patch changes only
the three key routes; existing startup and legacy desktop-entry routes remain
the user's baseline. These static chords do not supply a chat or workspace
identity. The direct window's empty links are asserted explicitly.

bundle, final Kitty 0.50 and loaded official 63db244 engine are hash-attested.

This changes no live desktop, owner checkout, service or deployment, and
