# Restore lease and buffered-input review

A final source audit found a concrete stable-holder race: two already-readable sockets could process a new leader's Init followed by an admitted older observer's Input in the same poll batch. Input reassigned leadership while the new client still borrowed Ghostty image storage for its streamed snapshot. The next PTY read could then mutate that storage. The actual pre-fix Nix binary reproduced the premature Resize/leadership response; the private test stopped only its own daemon to arrange the batch.

The fix holds leadership through snapshot completion and RestoreReady. Each admitted peer can retain one consumed input frame of at most4096 bytes while waiting; further reads from that peer pause. Replay occurs before calculating PTY input capacity, then buffered follow-on frames resume without requiring another socket edge. These additional buffers total at most64KiB across the existing16-client bound. A disconnected peer retains accepted input until it reaches the PTY; teardown remains bounded by the application's existing input backpressure.

A Resize received during restore retains only the latest8-byte geometry and applies after Ready, before later input. Actor geometry changes retain its worker pause barrier. Repeated Init closes only that offending connection before mutating snapshot/VT state: replacing a partially transmitted graphics frame with an error header would corrupt framing. Leadership changes now enqueue their Resize request before committing ownership; a full observer queue cannot abort the shared holder or discard its accepted input.

The final manual binaries passed three actual protocol cases each: Init+Resize in one write with a >4MiB graphics snapshot, duplicate Init refusal with the application retained, and input across a restore lease including two already-buffered frames without another socket edge. The stable race uses simultaneous ready sockets; the actor case respects its asynchronous Init barrier. Both also passed the nine existing losslessness/reattach gates, EOF-with-unready-observer regression, and actor stopped-worker ordering where applicable. See [SHA-indexed receipts](evidence/holder-restore-lease/index.json). No latency was collected; prior timings and native GUI proofs retain their original binary hashes. Exact final Nix artifact qualification is recorded separately.

The scope remains bounded: a foreground that withholds Ready can intentionally backpressure its own PTY. This patch adds no timeout, byte dropping, background cleaner, protocol namespace change or actor promotion.
