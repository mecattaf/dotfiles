# scroll on the physical seats

Branch `scroll/transition` (2026-10-01). The coordinator and the client run
[dawsers/scroll](https://github.com/dawsers/scroll) master instead of niri.
niri stays installed for rollback until it is retired.

## Where things are

| Piece | File |
|---|---|
| Package (master, pinned rev + hash) | `pkgs/scroll/default.nix`, overlay entry `scroll` in `overlays/default.nix` |
| NixOS module `programs.scroll` | `modules/scroll.nix` |
| Seat selection | `modules/display.nix`: `myDisplay.session` (`scroll` or `niri`), `myDisplay.keepNiri` |
| greetd | `modules/common.nix`: `scroll-session` (or `niri-session`) |
| RAW config | `home/dot_config/scroll/` → `~/.config/scroll` (out-of-store, like niri/) |
| Per-host slot | `~/.config/scroll-local.conf`, generated by `home/home.nix` |
| Colours | `~/.config/theme/scroll.conf`, rendered by `home/themes/default.nix` |
| CUBS shell module fragments | `~/.config/scroll/cubs.d/*.conf` (empty; never committed) |
| Config check | `nix build .#checks.x86_64-linux.scroll-config` |

## Session

greetd runs `scroll-session`, which re-execs through the login shell, imports
the environment into the user manager and runs `scroll.service`
(`restartIfChanged = false`, so a switch never kills the seat). scroll reads
`~/.config/scroll/config`, whose first line includes
`/etc/scroll/config.d/*`: the module's `10-session.conf` exports
`WAYLAND_DISPLAY DISPLAY SCROLLSOCK XDG_CURRENT_DESKTOP XDG_SESSION_TYPE
XDG_SESSION_DESKTOP` (never `SWAYSOCK` or `I3SOCK`, which would also reach the
headless browser sway) and starts `scroll-session.target`. When scroll exits,
`scroll-shutdown.target` stops `graphical-session.target`. herdr is not tied to
any of this.

Portals for `XDG_CURRENT_DESKTOP=scroll`: FileChooser is Nautilus through
xdg-desktop-portal-gnome, ScreenCast and Screenshot are xdg-desktop-portal-wlr
(output picked with slurp), Secret is gnome-keyring, everything else is gtk.
The module asserts, and checks at build time, that gnome-shell, mutter,
gnome-session and gdm are not in the system closure.

## Theming

MacTahoe on scroll exactly as on niri (non-negotiable). Home Manager's `gtk`
block (`home/home.nix`) keeps MacTahoe for GTK3 with its icons;
`home/theme.nix` points `~/.config/gtk-4.0/{gtk.css,gtk-dark.css,assets}`
through `~/.config/theme` at the selected theme's MacTahoe `gtk-4.0`;
`startup.conf` runs `theme apply` at login as `niri/startup.kdl` does, which
writes gtk-theme, icon-theme and an explicit `color-scheme` (never "default").
There is no libadwaita colour sheet. scroll has no blur, so MacTahoe's
translucent Nautilus surfaces are unfrosted here; blur belongs in the owned
scroll-based fork, not in GTK CSS.

## Tools

- Colour picker, `$mod+c` (niri `Mod+C`): `~/.local/bin/colorpicker`, slurp
  `-p` plus a native-scale grim PPM read, to the clipboard. No hyprpicker, no
  ImageMagick, no notification. On niri it stays `niri msg pick-color`.
- Monitors off: `scroll/scripts/monitors-off`, a one-shot `swayidle` to wake on
  input. No screen locker is bound (none ever was).
- piri and xwayland-satellite stay installed while niri is supported. piri runs
  only when `NIRI_SOCKET` is in the user manager; `scroll-session` unsets a
  stale one before importing its environment.

## Rollback

Set `myDisplay.session = "niri";` (per host or in `modules/display.nix`),
rebuild, reboot or restart greetd. While `keepNiri` is on, `niri-session` also
works by hand from a VT2 console. `nix flake check` stays green either way:
`home-profiles` evaluates the niri rollback in memory (niri-session, niri
portals, piri, xwayland-satellite, MacTahoe) and `scroll-config` always checks
the scroll config.

## Headless browser desktop

`modules/browser-desktop.nix` still runs stock sway; replacing it is for later.

## Master bump

There is no timer. By hand:

1. `git ls-remote https://github.com/dawsers/scroll HEAD`, then
   `nix-prefetch-url --unpack https://github.com/dawsers/scroll/archive/<rev>.tar.gz`
   and `nix hash convert --hash-algo sha256 --to sri <base32>`. Edit `rev`,
   `hash` and `version` in `pkgs/scroll/default.nix`.
2. Read what changed in the commands:
   `git log <old>..<new> -- sway/*.scd config.in meson.build subprojects/wlroots/meson.build`.
   Removed or renamed commands have happened inside minor releases
   (`frequency_ms`, `fullscreen_application`).
3. Check the build floors against nixpkgs: libdrm (>= 2.4.134 on 2026-10-01,
   exactly what nixpkgs has) and wayland-protocols (>= 1.48).
4. `nix build .#scroll` and `nix build .#checks.x86_64-linux.scroll-config`.
5. Report regressions upstream to dawsers with the old and new revs.

## Testing anything that starts a compositor

Only under `~/.local/bin/runtime-test --`, on the headless backend:

    ~/.local/bin/runtime-test -- env WLR_BACKENDS=headless WLR_RENDERER=pixman \
      WLR_LIBINPUT_NO_DEVICES=1 scroll -C -c <config>

`runtime-test` unsets `SCROLLSOCK` and `I3SOCK` (a scroll started with
`SCROLLSOCK` set adopts that path). Never run a test scroll on a live seat.
