# Local model roster

Anchor: 2026-08-03. This page is generated by reading the code, not the other
way round. Every claim below is checkable against three files:

- [`../../lib/local-models.nix`](../../lib/local-models.nix) — the typed
  catalog: artifact identity, pinned revisions, byte sizes, hashes, runtime
  arguments, `role`, and `status`.
- [`../../modules/strix.nix`](../../modules/strix.nix) — the coordinator's
  `services.local-models.allow`, `services.local-models.artifacts`, and
  `services.npu-llm.models`. These three lists are the entire download
  authority.
- [`../../flake.nix`](../../flake.nix) — assertions that pin the exact contents
  of all three lists, so the table below cannot drift silently.

**A catalog row is not a deployment.** Appearing in `lib/local-models.nix`
gives a model an identity and a pinned provenance record; it does not download
a byte. Only the per-host allowlists root weights into the Nix store, and only
`modules/local-models.nix` turns an allowed row into a llama-swap model.

## How a model reaches a host

There are exactly four ways, and every row in the table names one of them.

| State | Mechanism | Where it lands |
|---|---|---|
| **Served** | `services.local-models.allow` | Fixed-output Nix store paths rooted through `system.extraDependencies`, plus a llama-swap model row |
| **Rooted** | `services.local-models.artifacts` | Fixed-output Nix store paths and an `/etc/local-models/artifacts/<id>` link, with **no** llama-swap row |
| **Runtime-owned** | `services.npu-llm.models`, the catalog `utility` slot, or Voxtype's Home Manager service | Mutable runtime directories the tool manages itself; Nix declares only the allowed identity |
| **Cataloged** | Present in `lib/local-models.nix`, absent from every list | Nowhere. No download, no store path, no route |

`modules/local-models.nix` enforces the boundary: every entry in `allow` must
be a `canonical` row whose `backend` is a managed local backend and whose
`hosts` list contains this host. A `candidate` row cannot be allowlisted even
by mistake — the assertion rejects the build.

## Per-host split

Only the coordinator materializes models. `hosts/coordinator/default.nix` is the
sole importer of `modules/strix.nix`, and the catalog's `hosts` option is an
enum whose only member is `"coordinator"`, so no other host can appear in a
deployment row even in principle.

| Host | Local models | Notes |

| `coordinator` | Everything in the table below | Ryzen AI MAX+ 395 / Radeon 8060S gfx1151 / 128 GiB unified memory, plus the XDNA2 NPU |
| `zenbook-duo` | None | Imports no local-model module; its `pi` wrapper points at the coordinator's llama-swap |
| `nas` | None | Storage and media node; no inference role |

### Reconciling the totals

The catalog holds **15 deployment rows** (11 `canonical`, 4 `candidate`) and
**23 artifacts** across **209 pinned files** totalling **382,552,147,731 bytes
(356.28 GiB)**. That figure is the whole catalog including rows that never
download.

Of it, **19 artifacts / 205 files / 276,848,174,227 bytes (257.83 GiB)** are
actually rooted on the coordinator — the count `flake.nix` asserts. Because the
two Mage-Flow repositories share byte-identical components and Nix reuses those
fixed-output paths, the real on-disk figure is **267,564,622,488 bytes
(249.19 GiB)**; see [`mage.md`](mage.md).

The four **Cataloged** rows account for the remaining **105,703,973,504 bytes
(98.44 GiB)** that are never fetched.

Adding the runtime-owned FastFlowLM and Voxtype payloads to the Nix-rooted
logical total gives the 302,925,289,718-byte coordinator ledger in
[`deployment-decisions-2026-07-29.md`](deployment-decisions-2026-07-29.md).
That ledger predates this page's accounting of the `utility` slot and does not
include a figure for `qwen3:4b`; FastFlowLM owns those files and the repository
records no size for them.

## The NPU utility model

The catalog exposes one application-facing utility slot. Callers name only the
stable ID `utility`; they never name a concrete model. `lib/local-models.nix`
binds that ID to the `flm-qwen3-4b-utility` deployment (`qwen3:4b`, 32768
context), and `modules/npu-llm.nix` projects it into
`/etc/local-models/fastflowlm.json` and installs a `utility-model` wrapper.

The wrapper owns one start/request/stop cycle per request: FastFlowLM loads the
model, answers, and releases it. Idle NPU residency is therefore zero. This is
why `qwen3:4b` is absent from `services.npu-llm.models` — that option lists the
*additional* ad-hoc tags (`gemma4-it:e4b`, `gpt-oss:20b`), and the utility slot
is projected separately from the catalog. An assertion in `modules/npu-llm.nix`
requires the declared tags plus the utility slot to exactly equal the host's
canonical NPU catalog rows, so the two cannot diverge.

FastFlowLM never becomes a llama-swap peer. `flake.nix` asserts that no
`flm-`-prefixed systemd unit exists, that llama-swap has no peers at all, and
that the string `qwen3:4b` never appears in the rendered llama-swap settings.

## Voxtype and Parakeet

Live cursor dictation runs on the coordinator only, through
[`peteonrails/voxtype`](https://github.com/peteonrails/voxtype)'s
`onnx-migraphx` package, configured in `home/voxtype.nix`. The model is
`parakeet-unified-en-0.6b`. It is not a catalog artifact: Voxtype owns and
verifies its own mutable model directory, and the user service runs an
idempotent download before every start.

```console
voxtype setup --download --model parakeet-unified-en-0.6b --quiet
```

Weights land under `~/.local/share/voxtype/models/` and belong in neither Git
nor the Nix store. The bootstrap runs with a throw-away `XDG_CONFIG_HOME` so
that `setup --download`, which also persists its model choice to the default
config path, cannot fight Home Manager's immutable config symlink.

Model choice is constrained by the streaming path: upstream rejects the
similarly named `parakeet-tdt-0.6b-v3` when `streaming = true`, because that
model is batch-only. The selected unified model is the largest registry entry
compatible with the cache-aware TDT v3 streaming pipeline. The pinned streaming
window values (`0.32` / `5.6` / `0.32` seconds — 32/560/32 mel frames, each
divisible by 8) are load-bearing: Voxtype 0.7.5's implicit defaults fail
parakeet-rs's mel-frame divisibility check.

The first MIGraphX graph compile is slow; later starts reuse
`~/.cache/voxtype/migraphx`. Acceptance requires the journal to show the
MIGraphX execution provider initializing on gfx1151 with no CPU fallback.
`voxtype status --extended --format json` names the configured ONNX variant but
does not substitute for that journal check.

## Operating rules

- **No uncensored model is materialized.** All three uncensored rows are
  `candidate` and absent from `allow`, which the 2026-07-29 anchor states
  explicitly ([`tallies/2026-07-29.md`](tallies/2026-07-29.md)). Issue #109
  records an earlier 2026-07-25 disposition that, of the three, only
  `qwen3.6-35b-heretic` would ever be the one to materialize; the later anchor
  left all three cataloged, so promoting heretic remains an unmade decision, not
  a pending action. When it is made it is a deliberate edit to `modules/strix.nix`.
- Uncensored routes, if ever promoted, are high-recall hypothesis generators.
  Never an arbiter.
- `qwen3-coder-next` is cataloged only; its Q4 artifact is excluded by the Q8
  precision policy. The active coder models expose individual IDs, and any
  ensemble policy belongs in the caller, preserving each response and its
  attribution.
- The 8B OCR model drains by default. The 32B model is conditional refinement,
  not a permanently co-resident second server.
- The text-only and multimodal embedders stay separate model IDs so callers
  choose benchmark strength or mixed-modal retrieval explicitly. Re-embed any
  vectors persisted under the retired Q5 pipeline before comparing.
- FastFlowLM models are ad-hoc CLI workloads. Never configure `flm serve` units
  or add their model IDs as llama-swap peers.
- Mage-Flow is a diffusion pipeline and never a llama-swap row. Mage-VL earns a
  row only through upstream's custom SGLang branch, once packaged and proven on
  gfx1151/ROCm — never by relabeling it as llama.cpp or stock vLLM.
- Every served llama.cpp weight and external MTP head is Q8 (`Q8_0` or
  `UD-Q8_K_XL`), enforced by a flake assertion. Vision projectors, speech
  snapshots, tokenizers, and FastFlowLM's native NPU2 packages are explicit
  format exceptions, not low-bit selections.
- Distributed inference is not a catalog row. The `ds4` backend kind still has
  a renderer but no row selects it; the preserved operational lessons are in
  [`dual-node-inference-lessons.md`](dual-node-inference-lessons.md).
- Audio and video generation remain parked. Mage-Flow owns the selected
  image-generation and image-editing lanes.
