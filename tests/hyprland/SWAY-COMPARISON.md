# Staying on Sway: capabilities deferred

Decision, 2026-10-14: Tom keeps Sway. Hyprland work stops; native Solid/GPUIX shell work remains useful on Sway. Comparison is **stock Sway 1.12 versus Hyprland 0.56.0**, the versions inspected in this work, not old generalizations about either project. This covers the desktop architecture under discussion, not every configuration knob.

| Capability | What staying on stock Sway means |
|---|---|
| Background blur | No compositor blur behind translucent shell surfaces or windows. Alpha transparency still works, but reveals a sharp background. Hyprland implements `ext-background-effect-v1` with a BLUR capability. Current GPUIX npm binary does not use that protocol; our planned Hyprland path used transparent surfaces plus a compositor rule. [Hyprland protocol implementation](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/protocols/BackgroundEffect.cpp), [Sway globals](https://github.com/swaywm/sway/blob/1.12/sway/server.c). |
| Compositor animation | Defer animated window opening/closing/movement, workspace slides, layer-surface transitions and configurable animation curves. The shell can still animate its own contents. [Hyprland animation implementation](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/animation/AnimationManager.cpp), [Sway commands](https://github.com/swaywm/sway/blob/1.12/sway/sway.5.scd). |
| Compositor decoration | Defer rounded window clipping, drop shadows, glow, gradient borders, inactive/modal dimming and full-screen shaders. Shell-owned rounded UI/backgrounds remain possible. [Hyprland values](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/config/values/ConfigValues.cpp). |
| Layer-specific overrides | Sway supports ordinary layer-shell placement, anchors, exclusive zones and keyboard modes. Defer Hyprland namespace rules for blur, popup blur, alpha thresholds, dim-around, animation, intra-layer order, above-lock and exclusion from screen sharing. These overrides are distinct from basic layer-shell support. [Hyprland layer effects](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/desktop/rule/layerRule/LayerRuleEffectContainer.cpp), [Sway layer-shell implementation](https://github.com/swaywm/sway/blob/1.12/sway/desktop/layer_shell.c). |
| Tiling models | Keep Sway's explicit nested split tree, tabbed and stacked layouts. Defer Hyprland's built-in dwindle, master, scrolling-column and monocle algorithms and Lua layout providers. External Sway IPC layout scripts are possible, but are not the same native layout engine. [Hyprland layouts](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/layout/LayoutManager.cpp), [Sway layouts](https://github.com/swaywm/sway/blob/1.12/sway/sway.5.scd). |
| Grouped window tabs | **Retained:** Sway's native tabbed/stacked containers already group real windows. Hyprland-specific group locking, groupbar styling and drag-merge behavior are deferred. Chrome's internal browser tabs remain Chrome's responsibility in either compositor. [Sway layouts](https://github.com/swaywm/sway/blob/1.12/sway/sway.5.scd), [Hyprland group settings](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/config/values/ConfigValues.cpp). |
| Special workspaces | Sway has named workspaces, output association and a scratchpad. Hyprland's named special-workspace overlay behavior, with optional dim/blur of the workspace behind it, has no identical built-in Sway construct. [Sway commands](https://github.com/swaywm/sway/blob/1.12/sway/sway.5.scd), [Hyprland settings](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/config/values/ConfigValues.cpp). |
| Gestures | Keep swipe/pinch/hold bindings and per-device input settings. Defer Hyprland's continuous, finger-following workspace transitions and scrolling-layout gestures. Discrete swipe-to-workspace commands already exist in Sway. [Sway gestures](https://github.com/swaywm/sway/blob/1.12/sway/sway.5.scd), [Hyprland gesture settings](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/config/values/ConfigValues.cpp). |
| Extensibility | Keep external IPC services/scripts. Defer Hyprland's in-process native plugin API and Lua layout providers; neither is required for our shell. [Hyprland plugin API](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/plugins/PluginAPI.hpp), [Lua provider](https://github.com/hyprwm/Hyprland/blob/v0.56.0/src/config/lua/layout/LuaLayoutProvider.cpp). |

**No architectural loss for the core shell:** workspaces, window focus/movement, application launch, notifications, media/audio/network controls, clipboard/history and service-backed project context can live in the external Solid shell. Sway supplies event subscriptions, output/workspace/tree inspection and commands through its existing IPC. Window IDs are compositor-lifetime identities; durable Herdr sessions and project associations still belong in services. [Sway IPC](https://github.com/swaywm/sway/blob/1.12/sway/sway-ipc.7.scd).

**Input and display essentials remain:** Huion/tablet mapping, trackpad configuration, keyboard layouts, multiple outputs, fractional scaling, transforms, refresh rates, VRR and tearing. Do not claim HDR is Hyprland-only: Sway 1.12 documents `hdr`, 10-bit rendering and ICC/color profiles, with renderer/hardware limitations. These are capabilities, not proof that every mode works on Tom's hardware. [Sway input](https://github.com/swaywm/sway/blob/1.12/sway/sway-input.5.scd), [Sway output](https://github.com/swaywm/sway/blob/1.12/sway/sway-output.5.scd).

**Capture and protocols remain:** Sway 1.12 creates layer-shell v5, output management, screencopy, ext image-copy capture, foreign-toplevel capture and security-context globals. Screenshots, shell panels and future window previews are not inherently Hyprland-only. Implementing previews in GPUIX is separate work. Hyprland-specific protocol consumers need adapters; standard Wayland support is protocol-by-protocol, not a single “full Wayland” property. [Sway protocol registration](https://github.com/swaywm/sway/blob/1.12/sway/server.c).

SwayFX is an optional future fork, **not selected or installed**. Its own feature list includes blur, rounded corners, shadows, dimming, layer-shell effects and animation duration controls. This is its current upstream feature list; a chosen Nix package revision must be checked separately. That could recover selected visual effects while keeping Sway workflows, but does not establish complete Hyprland feature or protocol parity. No migration is necessary now. [SwayFX upstream](https://github.com/wlrfx/swayfx).

Evidence boundary: real nested Hyprland and a real kitty window worked with the explicitly test-only Aquamarine compatibility fixture. The native shell then exposed a bundling bug before mapping; the package was fixed subsequently. No successful Hyprland shell/blur screenshot or blur benchmark was obtained before Tom stopped that direction. Logs remain in `/tmp/hyprland-solid-smoke-cjx7sm6z`; no physical session was switched.
