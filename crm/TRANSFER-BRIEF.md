# TRANSFER BRIEF — reference corpora → Go CRM

**Purpose.** This document merges four deep-reads of the two reference repos — `jdanielnd/crm-cli` (Go + cobra + modernc.org/sqlite, our exact stack) and `dzhng/crm.cli` (Bun/TypeScript, the stronger product-design corpus) — into one set of transferable ideas for the implementing agents. Per doctrine: prior code is a reference corpus, not a rescue target. This is style transfer — each entry states the concept, its mechanics, and how to reproduce it idiomatically in our Go + SQLite shape. Nothing here overrides `SPEC.md`, `schema.sql`, or `KNOWLEDGE.md`; where a reference disagreed with a frozen ruling it appears under Anti-patterns or was dropped. Ideas are tagged **[v0.1]** (build tonight), **[v0.2]** (import/dupes/merge/export/skill era), or **[v2]** (deals/tasks/pipeline era).

Source shorthand: `crm-cli` = jdanielnd/crm-cli; `crm.cli` = dzhng/crm.cli.

## 1. Verb surface & ergonomics

**One error voice, one exit site [v0.1].** `main()` is `os.Exit(run())`; `run()` builds the root command, executes with `signal.NotifyContext(ctx, SIGINT, SIGTERM)`, and on error prints exactly one line — `crm: error: <msg>` — to stderr, returning `model.ExitCode(err)`. Cobra gets `SilenceUsage: true, SilenceErrors: true` so runtime errors never dump usage. `os.Exit` appears exactly once in the codebase. (crm-cli `cmd/crm/main.go:19-34`, `internal/cli/root.go:31-32`.)

**Explicit `init`; every other verb requires an existing DB [v0.1].** Both references silently create a brand-new empty database at whatever path `--db`/`$CRM_DB` names — so a typo'd path is indistinguishable from an empty CRM (crm-cli `internal/cli/root.go:76-82`). Invert this: `crm init` is the only verb that creates anything (DB, `notes/crm/`, `transcripts/YYYY/`), and it echoes the resolved path. Every other verb errors clearly when the file is absent: `crm: error: no database at /home/tom/mecattaf/notes/crm/crm.db (run 'crm init')`. This matters doubly for us — the DB lives in a git repo that may be unmounted or unfetched.

**Config precedence, stated once [v0.1].** `--db` flag > `$CRM_DB` > compiled default `~/mecattaf/notes/crm/crm.db`, documented as one sentence in exactly that order (crm-cli `internal/cli/root.go:57-83`; crm.cli `src/config.ts:207-219`). A persistent `--db` root flag is also what makes the whole integration-test harness work. Do **not** copy the auto-`MkdirAll` of explicit paths — see `init` above. crm.cli additionally strips global flags from argv before subcommand dispatch so `--db`/`--format` work in any position (`src/lib/helpers.ts:14-35`) — cheap and worth doing.

**Enum values as a single Go slice, reused everywhere [v0.1].** `var InteractionKinds = []string{"call","meeting","email","message","note"}` plus `ValidKind()`, consumed by: the validator (fail before opening the DB), the error message (`invalid kind: phonecall (must be one of: call, meeting, email, message, note)`), the `--kind` flag help via `strings.Join`, and cobra `ValidArgs`/flag completion. Add a test that parses the CHECK constraint out of `sqlite_master` and asserts the Go slice matches it, so DDL and code can never drift. (crm-cli `internal/model/types.go:233-308`, `internal/cli/task.go:91-93,121`; crm.cli `src/commands/activity.ts:43-47`.)

**Lifecycle transitions are their own verbs with distinct conflict semantics [v0.1].** `archive`/`unarchive` as verbs, not `edit --archived`. Copy the re-query-on-zero-rows idiom: `UPDATE ... WHERE id=? AND archived_at IS NULL`; on `RowsAffected()==0`, re-query to distinguish already-archived (exit 4, idempotent conflict — the retrying agent learns it already succeeded) from missing (exit 2). (crm-cli `internal/db/repo/task.go` `Complete()`.) Both references shipped soft delete with **no restore path** — an archived row was unreachable except via raw sqlite3. Add `crm unarchive (org|contact|interaction) <ref>`, make `ls --all` genuinely include archived rows (visibly marked), and let `show` work on archived rows.

**Positional sugar on the hottest verb [v0.1, optional].** Logging is the highest-frequency operation and the one most likely to be skipped under friction. Keep the frozen canonical grammar (`crm log --with <ref> --kind <k> --summary <s>`) — it is the right form for agents and repeated `--with` — but consider `crm log call nick "quick sync"` desugaring to it (crm.cli `src/commands/activity.ts:21-31`). Document exactly one canonical form in the skill.

**Aliases cost one line each [v0.1].** `contact`→`c`, `org`→`o`, accept singular and plural in `ls`/`show` selectors. Test each alias (crm-cli `internal/cli/relate.go:75-77` has the pattern and a dedicated alias test). Removes a whole class of "what was the exact word" friction for human and agent alike.

**Fill the verb matrix deliberately [v0.1].** crm-cli's interactions were write-once — no show, no edit, no delete for the entity that gets written most (`internal/cli/log.go:54`). Agent-written summaries *will* contain mistakes and the fix must not be manual SQL against a git-backed database. The frozen surface already has `show`/`archive`/`delete` for interactions; note that `edit` is frozen to `(org|contact)` only — if a mislogged interaction needs correcting in v0.1 the sanctioned path is archive + re-log. Flag `edit interaction` (summary/date/transcript) as a candidate surface extension for Tom to rule on; do not add it unilaterally.

**Idempotent re-runs are a feature [v0.1].** crm.cli's best ergonomic ruling: "a user should never see an error when merging data onto a record that already has that data." Setting a field to its current (normalized) value → silent no-op, exit 0. Repeating `--with nick --with nick` on `log` → one junction row (the frozen `UNIQUE(interaction_id, contact_id)` + `INSERT OR IGNORE` gives this free). Only a value owned by a *different* live record errors. (crm.cli `src/commands/contact.ts:276-282`, pinned by nine tests in `test/scenarios/messy-input.test.ts:32-190`.)

## 2. Reference resolution & errors

**One shared resolver, applied at every ref site [v0.1].** This is the load-bearing lesson from both repos. crm-cli implemented name resolution in exactly one command (`context`) and required numeric IDs everywhere else — including `log`, the daily-driver verb — so the daily loop became search → read id off a table → retype id (`internal/cli/log.go:77`, foreign keys typed as `Int64Var` throughout). Build `resolve.Contact(ctx, db, ref)` / `resolve.Org(...)` once, implementing the frozen ladder in SQL (never load-and-loop): numeric id → exact email (lowercased) → exact `name_norm` → substring on `name_norm`. Call it from every verb that takes a ref: `log --with`, `contact add --org`, `edit`, `show`, `context`, `archive`, `delete`, `find` follow-ups. Type every ref flag as `string`, never `int64`. (Ladder-as-ordered-function precedent: crm.cli `src/resolve.ts:16-112`.)

**Ambiguity is exit 3 with a pasteable candidate list — never first-match [v0.1].** Both references silently pick the first match on ambiguous names: crm-cli calls `Search(ctx, ref, 1)` and takes `people[0]` (`internal/cli/context.go:40-47`, ordered by `updated_at DESC` so the answer changes over time); crm.cli returns the first row of an unordered scan (`src/resolve.ts:99-108`) — which means `rm Nick --force` deletes an arbitrary Nick. Mechanically: query each ladder rung with `LIMIT 2`; on >1, return an `AmbiguousError{Ref, Candidates}` whose `Unwrap()` returns the `ErrAmbiguous` sentinel (so `errors.Is` classifies while `errors.As` extracts candidates), and print candidates on stderr in a form pasteable back as a ref: `contact 12  Martin Lévy  <m@x.fr>  @Acme`. Never let a destructive verb accept an ambiguous ref, even with `--confirm`.

**`ExitError` sentinel wrapper + one `ExitCode` switch [v0.1].** `type ExitError struct{ Message string; Err error }` with `Unwrap()` returning the sentinel; `NewExitError(sentinel, format, args...)` in the CLI layer (message written for the user), plain `fmt.Errorf("contact %d: %w", id, ErrNotFound)` wraps in the repo layer. One `ExitCode(err)` switch on `errors.Is` maps to the frozen table: 1 generic (including validation/usage), 2 not found, 3 ambiguous, 4 constraint/duplicate. Copy the 25-line table-driven test that pins the whole contract, including a double-wrapped case. (crm-cli `internal/model/errors.go:9-47`, `errors_test.go:14-38`.) Every sentinel needs at least one integration test that provokes it end-to-end — crm-cli defined `ErrDatabase`, mapped it to exit 10, documented it in the README, and *never produced it anywhere* (an exit code no code path can produce is a documentation lie). Optional, non-conflicting extension: a distinct code (e.g. 10) for "database absent/locked/corrupt" so a wrapper can tell "retry with different args" from "the store is broken" — but only if it is actually returned from `db.Open` failures.

**Error messages carry the remedy [v0.1].** House style from crm.cli, uniform enough to teach in one line of the skill: `Error: <what> "<value>" — <who/why>, <what to do>`. Not found → `contact not found: nick — try: crm find nick`, or when the miss was a link target, print the exact create command. Duplicate → name the current owner: catch the UNIQUE violation from modernc.org/sqlite, re-query the owning live row via the same normalized key, and emit `duplicate email "x" — already on contact 17 (Nick Dupont)`, exit 4. Never surface raw driver text (`FOREIGN KEY constraint failed` with an internal row id reached users in crm-cli, `internal/db/repo/interaction.go:83`). Invalid enum → list the legal set (§1). Validation of dates at the boundary: `time.Parse("2006-01-02", v)` before the INSERT so the user sees `invalid --date "next tuesday" (expected YYYY-MM-DD)` rather than a GLOB CHECK violation. (crm.cli `src/lib/helpers.ts:181-245`, `src/normalize.ts:18-21`; crm-cli `internal/cli/task.go:91-93`.)

**Resolve and validate every ref *before* opening the transaction [v0.1].** A typo in `--with` should fail with a good message and exit 2 without touching the DB; the FK/constraint is defense in depth, not the front line. (crm-cli's pre-check pattern in `internal/db/repo/tag.go` Apply; the counter-example is its `log` leaking FK errors.)

**Destructive confirmation reads `/dev/tty` and hard-refuses non-interactive [v0.1].** For `delete <ref> --confirm`: with the flag, proceed; without it on a TTY, prompt `Delete contact "Nick Dupont" (contact 17)? [y/N]` — note the *resolved* name and id in the prompt, so a mis-resolved ref is caught before the loss, not after; without it and no TTY, refuse with `refusing to delete without --confirm (non-interactive)`. Open `/dev/tty` directly (`os.OpenFile("/dev/tty", os.O_RDWR, 0)`) so the prompt works when stdin is a pipe; prompt on stderr. This composes with never-batched: `--format ids | xargs crm delete` keeps failing on the missing per-invocation confirmation. (crm.cli `src/lib/helpers.ts:58-78`.)

## 3. Storage & SQL patterns

**Single init funnel: open → `SetMaxOpenConns(1)` → pragmas → migrate [v0.1].** One exported `db.Open(path)` does everything and closes the handle on any failure; there is no way to obtain a connection that skipped pragmas or migrations. Pragmas as a `[]string` applied in a loop with per-pragma error context. Our list: `journal_mode = DELETE` (frozen — the reference's WAL is exactly what we forbid), `busy_timeout = 5000`, `foreign_keys = ON`, `synchronous = NORMAL` (or FULL; durability > speed here), `temp_store = MEMORY`, `cache_size = -64000`. Driver name is `"sqlite"` (blank-import `modernc.org/sqlite`). (crm-cli `internal/db/db.go:17-54`.) Add a startup assertion that the *actual* journal mode is not WAL (an externally created or hand-edited DB could reintroduce sidecars into the git repo) and a test against a real file path asserting `journal_mode` — `:memory:` reports `memory`.

**`SetMaxOpenConns(1)` and the deadlock it creates [v0.1].** The single most valuable Go+SQLite gotcha in the corpus. One pooled connection is what makes `:memory:` test DBs coherent and serializes writes — but any second query issued while a `*sql.Rows` is still open self-deadlocks (hangs until busy_timeout, doesn't error). Rule for our CLAUDE.md: **never call a repo method inside a `rows.Next()` loop** — drain into a slice, explicitly `rows.Close()`, then batch-load children with one `IN (?,...)` query fanned out through a map. This is exactly the shape `crm ls interactions` and `crm context` need to attach participants (`loadParticipants(ctx, []*Interaction)`). Give the regression test a timeout, since the failure mode is a hang. (crm-cli `internal/db/repo/interaction.go:150-171,213-256` — including the in-code comment that saves the next implementer an hour.)

**Embedded migrations versioned by `PRAGMA user_version` [v0.1].** `//go:embed migrations/*.sql`; on open, compare `user_version` to the pending files, apply each `-- up` section *and* the version bump inside one transaction (a failed migration leaves the version untouched). `PRAGMA user_version = %d` must be `fmt.Sprintf` — placeholders are illegal in PRAGMA; keep the explanatory comment so a reviewer doesn't "fix" it. Two deltas over the reference: derive the version from the filename prefix (`001_`), not the slice index (index-derived versions renumber silently if a file is ever removed), and copy the `.db` file before applying a migration — nearly free at personal scale, right insurance for a git-backed store. Our `schema.sql` becomes `migrations/001_initial.sql` (runner sets user_version; drop the literal pragma line from the file). (crm-cli `internal/db/db.go:13-14,56-137`.)

**Never split schema SQL on semicolons [v0.1].** crm.cli's `SCHEMA_SQL.split(';')` (`src/db.ts:88-93`) would shred our DDL: the six FTS triggers contain semicolons inside `BEGIN…END`. Execute each embedded migration as one string — modernc.org/sqlite handles multi-statement exec.

**Repository structs + column-list const + one polymorphic scan [v0.1].** `type ContactRepo struct{ db *sql.DB }`, package-level `contactColumns` string, and `scanContact(row interface{ Scan(...any) error })` serving both `QueryRow` and `Rows` — column order defined exactly once, adjacent to the list it must match. Include `provenance_sources`, `provenance_details`, `relationship_hint`, `archived_at` in every projection so provenance never silently drops. Alias the table unconditionally (`FROM contacts c` always) rather than string-replacing the column list when a join appears — crm-cli's `strings.ReplaceAll(personColumns, ", ", ", p.")` (`internal/db/repo/person.go:117-120`) is identifier surgery waiting to corrupt a query. (crm-cli `internal/db/repo/person.go:15-38`.)

**True PATCH semantics on `edit`: pointer inputs + `cmd.Flags().Changed()` [v0.1].** Update inputs are all-pointer structs; a field enters the dynamic SET clause only when the flag was actually typed, so `--email ""` clears while omission leaves untouched (three states: absent / present-empty / present-value). Repo builds `setClauses`/`args`, short-circuits `if len(setClauses)==0 { return FindByID(...) }` (no-op edit returns the record and — important for git-backed — does *not* fabricate an `updated_at`), appends `updated_at` only when something else changed, checks `RowsAffected`, and re-reads. Two upgrades: recompute `name_norm` in the same UPDATE whenever `name` is patched (the normalized column can never drift), and write one small helper/table instead of crm-cli's twenty-line if-block per field across five files. (crm-cli `internal/cli/person.go:226-253`, `internal/db/repo/person.go:161-228`, `internal/model/types.go:34-47`.)

**Transactions with defer-rollback on every multi-statement write [v0.1].** `BeginTx` / `defer tx.Rollback()` / inserts / `Commit`, with the post-commit `FindByID` *outside* the tx (a read on `r.db` while the tx is open deadlocks under one connection). `crm log` = interaction + N junction rows in one tx; the v0.2 importer = one tx per file, or per-row savepoints under `--skip-errors`. crm.cli had *zero* transactions and its merge path is the vivid failure: clear loser's unique columns → crash → loser half-destroyed, nothing merged. Under `journal_mode=DELETE` the transaction is also the unit of git-visible change. (crm-cli `internal/db/repo/interaction.go:47-92`; crm.cli anti-evidence `src/commands/contact.ts:467-524`.)

**Timestamps generated in Go, never `datetime('now')` [v0.1].** SQLite's `datetime('now')` emits `2026-03-08 14:22:01` — space-separated, no `T`, no `Z` — while our spec pins ISO-8601 UTC. crm-cli documented ISO and stored the other thing everywhere. Bind `time.Now().UTC().Format(time.RFC3339)` as a parameter; assert the format with a regex test on a fresh row. Same rule for the `occurred_on` default: compute `YYYY-MM-DD` in Go — `datetime('now')` would fail our GLOB CHECK. Never build two SQL shapes for present-vs-absent optional values (crm-cli's dual INSERT in `interaction.go:54-65`); compute the default in Go and keep one statement, one placeholder.

**Constraint-first dedup, decorated after [v0.1].** Do not enforce uniqueness by pre-scan — that is the TOCTOU race both references shipped (crm-cli `checkDuplicate` with zero UNIQUE indexes, `internal/db/repo/person.go:66-95`, skipping the check entirely when last name is nil; crm.cli full-table-scan `checkDupe*` under a proven 40-writer concurrent load). Our partial unique indexes are the mechanism; the application's job is to *catch* the violation and translate it (§2 owner-naming message, exit 4). A pre-check is permissible only to produce a friendlier message, and the constraint path must still be handled. Test: insert the same normalized name twice, assert exit 4.

**Canonical-on-write, never normalize-on-read [v0.1].** Store canonical, normalize the query to match. The reference enumerates the failure modes of raw storage: dedup becomes O(n) un-indexable work, lookups must normalize both sides, export→re-import creates duplicates on any byte difference. (crm.cli `spec/normalization.md:23-31`.) Concrete obligation for us: **lowercase email before insert** — the frozen `contacts_email_live` UNIQUE index is byte-exact, so `Jane@X.com` and `jane@x.com` would both insert unless the application canonicalizes. `name_norm` (NFKD, strip marks, casefold) is already frozen; apply the same discipline to email now, and to `website` if org-website dedup arrives.

**Three-tier normalization doctrine [v0.1 policy, v0.2 payoff].** Classify every normalizable field: **Strict** (reject invalid — `occurred_on`, `kind`, email syntax), **Permissive** (store as-is on parse failure — `website`, `phone`, `location`), **Extract** (best-effort canonicalization, never a gate — LinkedIn URL→handle, `name`→`name_norm`). Decide by asymmetry of false-rejection vs false-acceptance cost: a wrong canonical value corrupts every future lookup silently; a rejected weird-but-valid value blocks entry entirely. Express as paired Go functions `NormalizeX() (string, error)` / `TryNormalizeX() (string, bool)`; call sites choose the tier. Write the three-line policy into SPEC/DECISIONS so the v0.2 importer has a rule for the encoding-corrupted rows instead of inventing one per column. (crm.cli `spec/normalization.md:5-21`, `src/normalize.ts`.)

**Store the LinkedIn handle, not the URL [v0.1].** One regex (`(?:https?://)?(?:www\.)?linkedin\.com/(?:in|company)/([^/?#]+)`) applied on write; store `janedoe`, reconstruct the URL at render time. URLs vary five ways (protocol, www, trailing slash, query, locale) and every one defeats lookup. The investor CSVs contain URL-form values, so this does real work at import. Optionally add a linkedin rung to the resolve ladder. (crm.cli `spec/normalization.md:63-71`, `src/normalize.ts:106-143`.)

**Deterministic ordering with an id tiebreaker [v0.1].** `ORDER BY occurred_on DESC, id DESC` for timelines — `occurred_on` is a date with no time, and without the tiebreaker same-day interactions come back in arbitrary order, making the timeline unstable between runs (crm-cli has exactly this instability). NULL-last CASE ordering (crm-cli `internal/db/repo/task.go:90`) applies later to last-contacted sorts, where never-contacted rows sort last for "stale" views but first for "never reached" views — make the direction an explicit flag, not an accident.

**Per-invocation lifecycle [v0.1].** Open inside the command, `defer Close`, no daemon, no long-lived handle. This is what makes `busy_timeout=5000` sufficient for concurrent shell + agent use — no process holds a lock across think-time — and it lets migrations self-apply on first run after an upgrade. (crm-cli, all ~25 `RunE` bodies.)

**FK-blocked hard delete is a deliberate outcome [v0.1].** `interaction_people.contact_id` has no ON DELETE action, so with `foreign_keys=ON` a hard `delete contact` on someone with logged interactions will be rejected by SQLite. That is the right answer (the log is a historical record — "deleting a contact shouldn't erase the fact that you met"), but it must surface as a deliberate message, not raw FK text: `contact appears in 4 interactions — archive instead`, exit 4. (Doctrine: crm.cli `spec/data-model.md:98-103`, "orphaned references are informational".)

## 4. Search

**FTS5 external-content + AFTER triggers: confirmed, plus the untested trigger [v0.1].** Our frozen `schema.sql` already matches crm-cli's canonical form (`'delete', old...` command-form delete; update = delete+insert; trigger column lists must match FTS column order exactly — a mismatch fails at write time, not DDL time; `001_initial.sql:142-231`). What both references *missed* in tests: neither ever verifies the UPDATE trigger. Add a test that updates a row and asserts the old term no longer matches.

**FTS query escaping is mandatory [v0.1].** Raw user text containing `@ . - :` is FTS5 *syntax* and throws. Shared helper: quote as a phrase with inner quotes doubled, e.g. `"` + `strings.ReplaceAll(q, `"`, `""`)` + `"` — this is what makes `crm find nick@acme.com` work at all. But do not phrase-quote the *whole* query: tokenize first, quote each token, and join — per-token `OR` (bm25 will rank the all-terms hits up) or `AND`; pick one and document it. Whole-query phrase-quoting made every multi-word search an exact-adjacency match in crm-cli (`internal/db/repo/person.go:255-262`). Append `*` to the last token for prefix matching.

**bm25 via join, not `id IN (subquery)` [v0.1].** The `WHERE id IN (SELECT rowid FROM fts …)` shape both repos used consults the index as a *set* and discards the rank — results then order by recency and a typo-match beats a perfect match. Join instead:

```sql
SELECT c.<cols>, bm25(contacts_fts) AS rank
FROM contacts_fts JOIN contacts c ON c.id = contacts_fts.rowid
WHERE contacts_fts MATCH ? AND c.archived_at IS NULL
ORDER BY rank LIMIT ?
```

bm25 scores are negative, smaller = better, so plain ascending `ORDER BY rank` is correct. Optional per-column weights (`bm25(contacts_fts, 10.0, ...)`) to weight name above context. Archived rows are excluded by the outer WHERE (the FTS index still holds them — fine, they stay reachable by explicit ref).

**`crm find`: uniform cross-entity rows, globally rank-merged [v0.1].** Flatten heterogeneous hits into one shape — `{type, id, name, detail, rank}` — so one table/JSON array holds orgs, contacts, and interactions (`detail` disambiguates: contact→email/org, org→category/location, interaction→`occurred_on` + kind). Either `UNION ALL` the three per-table bm25 queries with `ORDER BY rank` in SQL, or merge-sort in Go — but never concatenate in fixed entity order (crm-cli did; a perfect interaction match ranked below a weak org match). Normalize scores across tables before merging if weights differ. Hard default cap (~20, `--limit` to change) so a broad query can't dump 1,800 imported contacts into an agent's context. `--type` filter validated early. (crm-cli `internal/cli/search.go:13-124` for the projection shape.)

**"Everyone at Acme" without denormalizing [v0.1/v0.2].** Our `contacts_fts` shadows real columns, so the org name has nowhere to live in the contact index. Don't add a cache column; run a second query at find time — contacts whose `org_id` is in the org-FTS hit set — unioned into the results. This yields the more useful output anyway: "the org matched, and here are its people," with zero cache invalidation. (Problem observed at crm.cli `src/lib/helpers.ts:249-269`, which chose denormalization and then needed a regression test to keep the cache honest.)

**`crm doctor` — index health and repair [v0.1, proposed small addition].** Trigger-maintained derived state *will* drift (bulk path bypassing triggers, hand sqlite3 session, bad git merge, restored backup) and external-content FTS desyncs silently. ~20 lines: `PRAGMA integrity_check`, `PRAGMA foreign_key_check`, per-table `INSERT INTO x_fts(x_fts) VALUES('integrity-check')` and count comparison, verify `journal_mode` is still `delete`, verify every `transcript_path` resolves on disk, report `user_version`. `--rebuild-fts` runs `INSERT INTO x_fts(x_fts) VALUES('rebuild')` per table in a transaction — also the escape hatch after the v0.2 CSV import. (crm.cli `src/commands/search.ts:146-178` for the status/rebuild verb pair.)

## 5. Output & formatting

**TTY-vs-pipe auto-detection [v0.1].** With no `--format` flag: human table when stdout is a terminal (`term.IsTerminal(int(os.Stdout.Fd()))`), JSON when piped. The single highest-leverage agent-first ergonomic in the corpus — the `/crm` skill never remembers `-f json`, the human never remembers `-f table`. Indentation is also TTY-conditional (compact JSON in pipes). One correction: an *unrecognized* `--format` value is a hard usage error listing the accepted set — crm-cli silently degraded unknown formats to a table, so `-f jsonl > out.json` exited 0 having written box-drawing characters (`internal/format/format.go:27-45,42-44`). And derive prettiness from the writer or an explicit param, not from `os.Stdout` inside a writer-parameterized function (their `outputJSON` bug).

**Empty collections are `[]`, never `null` [v0.1].** crm-cli json-encodes a nil slice, so every documented jq/fzf pipeline breaks on an empty DB — and its tests hid it by unmarshalling into a slice (which accepts null) instead of asserting bytes. Normalize in the formatter (`if data == nil { data = [] }`) and add integration tests asserting the literal bytes `[]`, a header-only CSV, and zero quiet-mode bytes for every list verb on an empty DB. (`internal/format/format.go:80-86`, `person_test.go:158-162`.)

**Declarative per-entity column projection [v0.1].** `format.ColumnDef{Header, Field}` lists per entity select what a human scans; the underlying record map carries everything, so JSON stays complete while the table stays narrow. This is exactly how the long provenance columns stay in `show`/JSON but out of the `ls` table without a second query. (crm-cli `internal/format/format.go:47-51`, `internal/cli/person.go:14-21`.) Complement with crm.cli's adaptive rule: hide any column where every row in the result set is empty (`src/format.ts:94-134`) — our orgs have ~13 columns of which most rows populate 4-5; this is the difference between `crm ls orgs` being readable and not. Use `text/tabwriter` (hand-rolled renderer ≈ 25 lines; skip the go-pretty dependency), rune-count widths (`utf8.RuneCountInString` — the corpus has accented names), and drop the rule line on non-TTY so `| grep` stays clean.

**Stable JSON keys with a derived display field [v0.1].** crm-cli omits nil fields from JSON entirely (sparse maps). Prefer the inverse for record output: a stable key set with explicit `null` — agents write `.[].email` without presence checks. Steal the *derived-key* half: emit a computed `display`/`ref` field so consumers have one canonical label without concatenating. Never let a key's type vary. Most idiomatic route: `json` tags on the model structs, marshal directly for JSON, and keep a small map path only for table/CSV — avoids hand-writing ~20-branch `xToMap` per entity.

**`-q` / `--format ids` as the composition primitive [v0.1].** One bare ref per line, handled once in the formatter so it works uniformly on `ls` and `find`. This is what replaces a combinatorial explosion of batch flags: `crm ls contacts --format ids | xargs -n1 crm context`. Because `find` spans entity types, emit *prefixed refs* — `c12`, `o4`, `i9` — and have the resolver accept them as an exact-match tier (rejecting a mismatched prefix with a clear error). Prefixed refs make piped output self-describing and any future polymorphic verb possible. (crm-cli `internal/format/format.go:54-78`; crm.cli `src/format.ts:24-29`, README recipes; prefix doctrine `spec/data-model.md:23-29`.)

**stdout = data, stderr = messages — with zero exceptions, proven by tests [v0.1].** Frozen rule; the transfer is the enforcement mechanics. Confirmations (`Archived contact 17`) → stderr; the error line → stderr; and — the observed failure mode — *first-run/setup notices too*: crm.cli printed config-creation prose to stdout so the first-ever `list --format json | jq` in a fresh environment failed to parse (`src/config.ts:166-170`). Make it structural: only the output formatter may touch `os.Stdout`. Every integration test asserts the stream, not just the content.

**Every mutation echoes the full resulting record — including lifecycle verbs [v0.1].** Re-read after write, emit through the normal formatter, in the same shape `show` produces; single-record commands emit a one-element *array* so `add`/`edit`/`show`/`ls` all produce `[]` and consumers never branch on shape. Close the gap both references left: `archive`/`unarchive`/`delete` also emit the affected record (with `archived_at` populated) — crm-cli's lifecycle verbs printed only a stderr sentence, so `crm archive X -f json` yielded nothing; crm.cli's `log` printed *nothing at all* on success, making chaining impossible. (crm-cli `internal/db/repo/person.go:41-64`.)

**`context <ref>` gets its own renderer — the only verb that does [v0.1].** A briefing is a document, not a row set. Human form: `# Nick Dupont (contact 17)` + profile lines (including `relationship_hint`, `context`, provenance — "how do I know this person" is the first thing a briefing needs) + org block + `Timeline (N):` with `i43  2026-07-29  call  summary` rows + **transcript path rendered prominently per entry** (the file is the evidence of record). JSON form: one object `{contact, org, timeline: [...]}`. CSV/TSV deliberately coerce to JSON (an aggregate has no tabular shape). Empty sections are omitted entirely — no `Deals (0):` headings, no empty keys in the briefing (omission is for briefing *sections*; record *fields* keep stable keys per above). Section headings carry counts. Cap the timeline (default ~20, `--limit`/`--all`) so a 200-interaction contact doesn't blow a context window. Build it as one assembler returning a `Briefing` struct with two renderers — never two inline builders (crm-cli's CLI and MCP context handlers were separately written and diverged within one release). (crm-cli `internal/cli/context.go:73-227`; crm.cli `src/fuse-json.ts:108-168` for the self-contained/capped shape.) Document the cost ladder in the skill: `show` (cheap) → `show --with-*` (one join, opt-in relation expansion, crm-cli `internal/cli/org.go:134-176`) → `context` (everything).

**Display form vs storage form [v0.1].** Human coercions (relative dates, `—` for null) live strictly inside the table/briefing renderers, driven by *typed field knowledge* — never by regex shape-sniffing of values (crm.cli's `displayValue` mis-formats any text that happens to look like a timestamp) and never smuggled through the data as `_display_*` side-channel keys. `--format json` always emits raw stored canonical values.

## 6. Testing

**Integration harness: build once in TestMain, exec the real binary [v0.1].** The single highest-value file in either repo. `TestMain` builds `./cmd/crm` into a temp dir (locating the module root by walking up for `go.mod`); a helper `crm(t, dbPath, args...) (stdout, stderr string, code int)` prepends `--db`, captures both streams, extracts the code from `*exec.ExitError`. This tests the actual contract — the three things a user or agent observes — and catches stream leakage, exit-code regressions, and JSON-shape changes that unit tests structurally cannot. Fresh `t.TempDir()` DB per test (which, unlike `:memory:`, exercises the real journal mode); tests can and should `t.Parallel()` (crm-cli's package-level flag globals are why *it* couldn't — keep flags in a struct captured by closures instead). Borrow crm.cli's runner ergonomics: `OK()` fails loudly embedding both streams, `Fail()` fails if it *succeeded*, `JSON(&v, ...)` parses, `WithEnv()` tests `$CRM_DB` precedence. (crm-cli `internal/cli/person_test.go:17-75`; crm.cli `test/helpers.ts:26-96`.)

**Unit fixtures: `db.Open(":memory:")` + `t.Cleanup` in one `dbtest` package [v0.1].** Four-line sub-millisecond setup that runs the real migrations (so the migration runner is exercised by every repo test). Put the helper in one `internal/db/dbtest` package (crm-cli duplicated it six times), with a `NewFile(t)` variant for anything that must observe `journal_mode=DELETE`.

**The concurrent-writer test, calibrated, with the sidecar assertion [v0.1 — mandated].** N parallel *processes* (exec the built binary — `-race` sees nothing across processes, and the realistic contention is two shells or shell+agent) each running `crm log` against one file DB; assert every one exits 0 and `SELECT count(*)` = N. Copy the calibration discipline: crm.cli's comment records that N=20 didn't reliably contend but N=40 produced ~4 SQLITE_BUSY failures without busy_timeout — a magic number turned into evidence; surface the first child's stderr on failure. Then the assertion that matters most for us: **after the run, `os.Stat(dbPath + "-wal")` and `-shm` must return NotExist** — one line that mechanically enforces the DELETE-journal non-negotiable. (crm.cli `test/db-busy-timeout.test.ts:6-55`.)

**Persona scenario tests as executable product specs [v0.1].** One file per real workflow, opening with a banner comment (persona, context, "why this scenario matters" bullets), one long test walking a multi-day session against the real binary, structured by `// ── Day 2 ──` step comments, ending with a full final-state verification. Write these *before* the implementation — they double as the spec for verb interaction. Ours: (1) **first lead** — org add, contact add, backdated `log --body-file` from paper notes, `context nick`; (2) **post-call** — transcript file + `log --kind call --transcript`, `context` shows both interactions in order with the path; (3) **messy refs** — accented names, `Léger`/`Leger` resolving to one row, ambiguous surname → exit 3 with candidates, re-add → exit 4 naming the owner, archive hides from `ls` but not `ls --all`; (4) **agent session** — find → context → log, all `--format json`; (5) [v0.2] **import** — run twice, second run 100% skipped, provenance appended not overwritten. The messy-input persona is what actually happens during the 1,812-row load. (crm.cli `test/scenarios/*` — eight personas; `messy-input.test.ts` is the standout.)

**Distinguishing assertions per claimed capability [v0.1].** The sharpest lesson from crm.cli: 337 green tests coexisted with a `find` command whose documented semantic search was actually a word-overlap counter — because no test asserted anything a stub couldn't satisfy. For every claimed mechanism, write the assertion only the real mechanism passes: ranked search → a strong match *outranks* a weak one (not "results non-empty"); normalization → `Léger` and `Leger` hit the same row; idempotent import → second run reports all-skipped and the count is unchanged; provenance → re-import *appends* a source; `--verbose` (if added) → output differs from non-verbose; exit codes → asserted numerically, not `!= 0`. Documented README/skill recipes are themselves executed as tests — crm-cli's fzf recipe was silently broken by its own null-on-empty bug.

**Export→import roundtrip test [v0.2, the day `export` lands].** Cheapest test catching a whole class: CSV escaping, ` || ` separator survival in `provenance_sources`, embedded newlines in `body`, NULL vs `''`, unicode in corrupted names. Assert row-by-row struct equality, not counts. (crm.cli `test/import-export.test.ts:366-390`.)

## 7. Agent-first design (skill & docs)

**The `/crm` skill is workflow-shaped, not flag-shaped [v0.2].** The best artifact in either repo is crm-cli's `AGENT.md`: organized by *user situation* with numbered call sequences — "when the user mentions meeting someone → 1. search 2. create if absent 3. log 4. update dossier 5. …" — plus judgment no schema can express ("always search before creating", "append, never overwrite"). Situation-indexed instructions get followed; endpoint-indexed references get ignored. Our situations: *just got off a call* → `find` → `contact add` if absent → `log --kind call --with … --summary … --transcript <path>` → append to `context` via `edit`; *about to talk to X* → `crm context X`; *mentions a new company* → `org add` with provenance flags. Structure per crm.cli's `skills/SKILL.md`: frontmatter with triggers in `description` (pi ignores `when_to_use`), verbs with one runnable example each, exit-code table, stdout/stderr rule, transcript protocol — with the exhaustive flag reference pushed to a sibling file for progressive disclosure. Ship skill edits in the same commit as the verb they document. (crm-cli `AGENT.md:9-113`; crm.cli `skills/SKILL.md:1-479`.)

**Close with a "Tips for AI Agents" block [v0.2].** The highest-leverage ~12 lines: flag tables say what's *possible*; this says what's *cheap and idiomatic*, collapsing the agent's search space. Ours: prefer `context` over show+ls; refs accept name/email/id — don't look up ids first; exit 3 = ambiguous — re-ask the human, never guess; long notes go in a transcript file via `--body-file`/`--transcript`, never 5k words into `--summary`; `find` is bm25-ranked — real words, not globs; never hand-edit crm.db (FTS triggers desync; use the CLI, repair with `crm doctor`). (crm.cli `skills/SKILL.md:466-479`.)

**The living dossier: ratify `context` as the agent-owned column [v0.1 doctrine].** Separate the immutable event log (`interactions`) from mutable current-understanding: `contacts.context`/`orgs.context` = agent-maintained rolling dossier (preferences, dynamics, timelines — read before every conversation, appended after), `relationship_hint` = how Tom knows them, `interactions.summary` = per-event immutable. Write the append-don't-overwrite rule into the skill with a worked example (crm-cli ships a 7-bullet model dossier, `AGENT.md:40-59`); consider `--context-append` on `edit` so an agent holding stale state cannot clobber.

**Simulated agent transcripts as documentation — written first [v0.2].** Two or three full annotated conversations in the skill/README using our real verbs (user prose → the exact `crm …` calls → the agent's reply). Highest-value one: the post-call flow. Writing the transcript *before* the code surfaces grammar friction cheaply. (crm-cli `docs/index.html` use-case tabs.)

**Orientation doc where the data lives [v0.1].** `~/mecattaf/notes/crm/README.md` (the `llm.txt` idea): DB is authoritative; transcripts under `transcripts/YYYY/` are evidence of record and summaries never replace them; ref-resolution rule; never hand-edit crm.db. An agent that stumbles into the directory with no skill loaded becomes competent in one read. This also discharges the pending notes/CLAUDE.md amendment for the `crm/` lane. (crm.cli `src/fuse-json.ts:9-82`.)

**Help text is the agent's API [v0.1].** Enum flag help generated from the enum slices (can't go stale); `Example:` blocks on every verb showing one full realistic invocation (crm-cli had zero — the cheapest high-value gap); `Long:` prose on `context`, `find`, `log`. Then the skill can legitimately say "run `crm <verb> --help`" instead of duplicating the flag list.

**Transcript filenames: date-first slug [v0.1].** SPEC says only "markdown files"; adopt `transcripts/2026/2026-07-29-nick-dupont-call.md` — date-first so `ls transcripts/2026/` is a chronological index for free; one `slugify` (lowercase, non-alphanumeric runs → `-`, trim) shared with any future export tree. (crm.cli `src/fuse-json.ts:84-106`.)

## 8. Daily-workflow ergonomics

**`crm status` — a zero-argument front door [v0.1, proposed small addition].** A CRM you must query to get anything out of is a write-only database. Five cheap COUNTs through repo functions (not raw SQL in the command), reachability-first content: `N orgs | N contacts | N interactions`, `last logged: YYYY-MM-DD (N days ago)`, `N contacts never contacted`, `N not touched in 90d` — plus the resolved DB path, so a mis-set `$CRM_DB` is visible at a glance. Dual output like everything else; it doubles as the agent's session-opening call and as a DB-reachable smoke check. `COALESCE` aggregates so empty sets yield 0 not NULL. (crm-cli `internal/cli/status.go:26-132`.)

**The stale/never-contacted report [v0.1 or early v0.2].** *The* query for a reachability-first CRM, and the one most commonly written wrong: an inner join on `MAX(occurred_on)` silently drops never-contacted people. The correct shape:

```sql
SELECT c.id, c.name, MAX(i.occurred_on) AS last
FROM contacts c
LEFT JOIN interaction_people ip ON ip.contact_id = c.id
LEFT JOIN interactions i ON i.id = ip.interaction_id AND i.archived_at IS NULL
WHERE c.archived_at IS NULL
GROUP BY c.id
HAVING last IS NULL OR last < date('now', ?)
ORDER BY last IS NOT NULL, last
```

`--format ids | xargs -n1 crm context` turns it into a morning outreach briefing. Render `last: never` explicitly. (crm.cli `src/reports.ts:21-76`.)

**Composition recipes as documentation — and as tests [v0.1].** A README section stating the three guarantees (stdout=data, stderr=messages, structured exit codes) then proving them with 3-4 copy-pasteable pipelines: fzf-pick → `context`; `ls contacts -f json | jq` for never-contacted; `find X --format ids | xargs -n1 crm show`. Every documented recipe runs in an integration test. (crm-cli `README.md:179-197`.)

**`post-write` shell hook: the git-commit seam [v0.1-optional / v0.2].** A config-declared shell command fired after mutations, entity payload as JSON on stdin, 30s timeout, exit status ignored (fire-and-forget). This is where `git -C ~/mecattaf/notes add crm/ && git commit -m 'crm: log call with Nick'` belongs — commit hygiene stays out of the binary and out of every verb, consistent with the no-ceremony ruling because it's user config, not tool behavior. Also the natural seam for kicking off batch ASR when a `log` carries `transcript_path`. Ship one `post-write` event, not the reference's 20-name matrix; add pre-hook veto only when something needs it. Go: `exec.CommandContext` + timeout ctx + `cmd.Stdin = bytes.NewReader(payload)`. (crm.cli `src/hooks.ts:5-24`.)

**Auto-create on link: documented, opt-in only [v0.2 import era].** crm.cli auto-creates a stub org/contact whenever a link flag fails to resolve — which converts every typo into a permanent entity, silently (`"Acme Crop"` becomes a company; the repo's answer to the resulting mess is its own `dupes` command). Keep `log --with` and `contact add --org` strict: resolution failure exits 2 and *prints the exact create command to run*. If import throughput ever wants auto-create, gate it behind `--create-missing`, stamp the stub's `provenance_sources` with `auto-created by crm <verb>`, and announce the creation on stderr. Keep the reference's one good habit: publish the matrix of which flags may create what, in SPEC. (crm.cli `src/lib/helpers.ts:101-161`, `README.md:468-482`.)

**Import safety triad + reject file [v0.2].** `crm import (orgs|contacts) <csv> [--dry-run] [--skip-errors] [--update] [--source <label>]`, always ending with `Imported: N, skipped: N, errors: N` on stderr (created refs on stdout). Default on an existing match (org `name_norm`, contact `email`) is *skip*, so re-running is idempotent by default — and the acceptance test is exactly that: run twice, second run 100% skipped, row count unchanged. `--update` appends `provenance_sources` with the ` || ` join, never overwrites. `--reject-file` captures failed rows with line numbers — the encoding-corrupted rows become a reviewable worklist instead of a silent loss. `encoding/csv` with `LazyQuotes`, `FieldsPerRecord=-1`; one transaction per file, per-row savepoints under `--skip-errors`; numeric-looking text guarded before int coercion. (crm.cli `src/commands/importexport.ts:66-203`.)

**`dupes`: two-metric scoring, named reasons, strictly read-only [v0.2].** Score name pairs with `max(normalized-Levenshtein, Dice-bigram)` — the two metrics fail on opposite cases: Levenshtein catches typos/transpositions but scores `Acme` vs `Acme Inc` badly; Dice catches containment. Accumulate a weighted score from *named reasons* (same email 0.5, identical `name_norm` 0.5, similar name 0.4, same website registrable domain 0.2, shared non-free email domain 0.15 — exclude gmail/yahoo/hotmail/outlook or the signal is noise), capped at 1.0. Output `{left, right, score, reasons[]}` — reasons make suggestions auditable in a way a bare number never is. Compare on `name_norm` using `[]rune` (accent corruption). O(n²) over 1,135 orgs is milliseconds. **`dupes` never mutates**; `merge` is a separate, human-initiated verb. Seed the fixture from the 22 parked calls in investor-crm's `dedup-review.csv`; `dupes` should be able to regenerate that file. (crm.cli `src/commands/dupes.ts:97-236`, `src/lib/helpers.ts:492-540`.)

**Merge mechanics [v0.2].** One-sentence memorizable contract: "keeps the first, absorbs the second." Order of operations is the non-obvious part: inside **one transaction** — (1) null the loser's UNIQUE-constrained columns (`email`, `name_norm` via archive) *first* or the winner's update trips the partial index; (2) `COALESCE` scalars winner-first; (3) **concatenate** `provenance_sources`/`provenance_details` with ` || ` — merge is exactly where provenance must accumulate, not be chosen; (4) repoint references, handling the junction UNIQUE with `INSERT OR IGNORE INTO interaction_people SELECT interaction_id, <winner> ... ; DELETE ... WHERE contact_id = <loser>`; (5) soft-archive the loser (reversible) rather than delete; (6) print the surviving ref. Relink-before-archive so the operation is independent of delete-cascade policy. (crm.cli `src/commands/contact.ts:436-526`, `spec/data-model.md:101`.)

**`export --tree`: a diffable markdown projection [v0.2/endgame].** The durable 5% of crm.cli's 2,600-line FUSE effort is its no-daemon static export. For us: `crm export --tree` writing **markdown, not JSON** — `contacts/<slug>.md` with YAML frontmatter (id, org, email, provenance) and the timeline as prose, relative links to transcripts, one generated `index.md`. Because the notes repo is git, `git log -p` then shows *what changed about a person* in reviewable English — an audit trail the binary `.db` can never give. Regenerate from the `post-write` hook. Strictly read-only and derived (one write path, ever); one file per entity — never file-copy index directories (crm.cli copies each contact up to eight times into `_by-*/` dirs, which for a git repo means unreadable diffs and superlinear growth). Drop the orientation README at the tree root. (crm.cli `src/export-fs.ts:41-327`, `spec/fuse-implementation.md:119-123`.)

**[v2] Deals/pipeline, when they come.** Stage transitions as append-only events with real columns (`from_stage`, `to_stage`, `note`, `occurred_at`) plus a denormalized `deals.stage` current-value cache — the reference's event-log doctrine is right (single source of truth, timestamps free, INSERT-safe under concurrency) and its encoding was wrong (see anti-patterns). Reject no-op moves with a distinct error — it surfaces an agent's stale mental model immediately. `--note` on every transition captures the why at the moment of change. Enum-like taxonomies that change as project decisions (pipeline stages; also `orgs.category`, currently drifting with ~375 `other` rows) can live in config validated at write time rather than in DDL — the frozen `kind` CHECK is the right opposite choice for a five-value enum that never changes. (crm.cli `spec/data-model.md:31-77`, `src/commands/deal.ts:357-414`.)

## 10. Anti-patterns observed

Failure modes seen in the references, kept short — the countermeasure is in the sections above.

- **WAL + git/cloud-sync recommended in docs** (both repos; crm-cli's README even suggests iCloud). The exact corruption path our DELETE-journal ruling forbids. Enforced here by the pragma, the doctor check, and the no-sidecar test assertion.
- **Docs describing capabilities the code doesn't have** — three independent drift modes in crm-cli (marketing copy, changelog claims, its own CLAUDE.md listing five nonexistent files and prescribing unimplemented pragmas/backups/date-parsing); crm.cli documents ONNX semantic search across three surfaces while shipping a word-overlap counter, with *three different model names* in docs vs code, and its mounted agent doc contradicts its README on write semantics. In the agent era this is worse than stale docs: an agent plans around the phantom capability and can't tell it failed. Rule: CLAUDE.md/SPEC/skill describe only what exists (aspirations go in issues), every doc claim has a distinguishing test, and no aspirational constants left in code.
- **Two agent surfaces, divergent grammars** — crm-cli's CLI and MCP accepted different shapes for the same operations and diverged within one release at ~4% test coverage; crm.cli's CLI does partial edits while its FUSE mount does full-document replacement. The empirical case for our CLI-only + skill ruling. If a second surface ever exists, it calls the same repo functions.
- **FUSE/NFS as a surface** — 2,600 lines, a library graveyard, two documented macOS kernel-panic classes; the 327-line static export delivered the value. When a design doc contains a graveyard section, the fallback in that doc is the product.
- **ID-only ergonomics + first-match ambiguity** — the two halves of the resolution failure (§2); the second is silent data corruption, not a UX wart.
- **Dedup by application pre-scan without DB UNIQUE** — TOCTOU under both repos' own concurrency assumptions; also blind spots (name check skipped when last name nil; orgs never checked at all).
- **No transactions on multi-statement writes** — merge is the vivid case: crash mid-sequence leaves states no verb can describe, and under DELETE-journal, a half-applied merge is a half-corrupt git commit.
- **FTS without bm25 / `id IN (subquery)` rank discarding; whole-query phrase quoting** — search degrades to recency-ordered noise exactly as the corpus grows past a few hundred rows.
- **Structured facts encoded as prose, recovered by regex** — `"from lead to qualified | note"` parsed by `/from (\S+) to/` in six files; a stage name with a space breaks every report. If a fact matters, it is a column; the tell is the same regex in more than one file. Never parse `summary`/`body` to recover a fact.
- **Whole-table scans for resolution/dedup/detail** — JSON-array columns can't be indexed, so every access degraded to load-and-loop (O(n²) import). Storage shape determines query shape; the concrete reason to keep resisting a `custom_fields` JSON bag next to our indexed scalar columns.
- **Silent leniency**: unknown `--format` degrading to table; FTS parse errors silently falling back to `LIKE`; "safe" JSON helpers returning a differently-typed value on parse failure (corruption surfaces as a TypeError frames away); flags registered in `--help` but never read (`--verbose`, `--no-color`); mutations printing nothing; empty results as `null`; config notices on stdout. All the same disease: a failure or notice made invisible to the consumer.
- **Redundant free-text `company` beside the `org_id` FK** — the second-order damage is the point: the denormalized column captured the FTS index and the default table view, so the *wrong* data path looked better than the right one. One representation; index the org name by query-time join.
- **Soft delete with no restore and no visibility** — "recoverable" in the README, recoverable only via raw sqlite3 in reality. A verb must recover it or it isn't soft.
- **Create-on-first-use vocabularies with no normalization** — `vip`/`VIP`/`Vip` as three tags; relevant to our free-text `category` and any future tags: normalize, UNIQUE the norm, suggest nearest-existing before minting.
- **Config keys owned by the wrong feature; presentation values smuggled through the data model; per-field date/datetime strings accepted unvalidated** — smaller warts, all countermeasured above.

## 11. Net-new vs the July audit

Only items the existing STEAL/AVOID list in `KNOWLEDGE.md` did **not** already capture (the list already holds: layering, sentinel→exit mapping, FTS5 external-content + triggers, `context` briefing, resolve-by-anything, stdout/stderr, busy_timeout + concurrent-writer test; avoid: doc drift, redundant company column, missing transactions, ignoring bm25, dedup without UNIQUE, ID-only ergonomics, FUSE, second agent surface; critical: DELETE not WAL).

1. **TTY-vs-pipe format auto-detection** (table on terminal, JSON piped) — zero-flag dual audience.
