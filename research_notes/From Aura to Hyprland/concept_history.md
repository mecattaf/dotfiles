# The recurring concept beneath Agency, COWL, CADE and CUBS

## What has Tom actually been trying to make?

### Takeaway

The enduring object is an owned, coherent computing environment in which human work, agent work, durable knowledge and the graphical workspace remain connected. It is simultaneously a place to act, a place to see what is happening, and a means to return to the context that produced it. Neither Chromium nor a specific agent framework is the underlying goal. The latest user instruction explicitly supersedes the Aura requirement; the history supports preserving the interaction model while replacing its implementation.

### Inferences for the new direction

The next surface should retain three interaction scales: an ambient shell, a complete graphical workspace, and full domain applications. A command palette alone cannot satisfy the collected requirements. Nor can an agent transcript viewer, however attractive. The interaction worth carrying is: open a project/workspace, see its windows and ongoing agents, inspect and steer their work, manipulate the actual application, and return later without losing the thread.

The July service/surface split makes the new toolkit direction conceptually less disruptive than a browser rewrite: preserve durable service contracts and session identity while replacing presentation. This is an architectural inference, not a finding that GPUIX already implements every necessary surface, terminal or browser embedding capability.

The strongest reason to use a fixed Hyprland substrate is the May principle: subtract variability so depth becomes affordable. That does not imply importing the old kitty-only/local-model-only constraints into a different project.

## Which sacred cows should be turned into burgers?

### Takeaway

Several cherished architectural “necessities” were assistant arguments constructed around a particular implementation, rather than user-level requirements. The most valuable historical work is the interaction model, failure evidence and authority boundaries; the least defensible inheritance is the claim that a coherent experience must have one binary, one renderer or one browser fork.

Yet the document itself defines signals as external typed streams and delegates geometry to niri. The assertion of exclusivity is assistant-authored and unsupported by a necessity proof. Unified behavior does not itself establish same-process execution as a requirement. The latest user instruction retires Aura explicitly. ### Unknowns and proposed defaults

- **What is a workspace's authoritative identity now?** Default: bind existing project/session/service IDs to Hyprland views; do not make window IDs the sole durable identity. This is a proposed translation of June29's capture concept, not a discovered current schema.
- **Which surfaces must be native, browser-rendered or ordinary applications?** Default: preserve the graphical requirements first and let current-technology research establish which surfaces GPUIX can reliably host. No automatic restoration of Aura, browser ownership or webview embedding.
- **How much productization belongs in the first usable environment?** Default: a complete, daily-usable interaction path over existing services and real sessions. Defer an installer marketplace or generalized app platform unless this path requires it. This preserves Tom's whole-domain quality bar without inheriting every old Chromium prerequisite.
- **Is the aim a personal environment or a distributable enterprise product?** Current evidence permits both historically. Default: make Tom's actual environment coherent first, with domain/service boundaries that permit later distribution; do not manufacture a current commercial commitment.
- **Does SolidJS mean web compatibility or reactive authoring?** The sibling Chromium researcher identifies the primary March30 chat as the decisive source: Tom explicitly explores SolidJS and rapid reactive shell behavior, but also says the exact framework can change. The new user message makes its lineage newly relevant. Resolve the retained API/authoring expectations against GPUIX, rather than claiming that JSX entails DOM/CSS/browser equivalence.
